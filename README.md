# ТокТок AI туслах

TokTok (www.toktok.mn, хоол хүргэлт)-ын **хүргэгч (driver)**, **ресторан / харилцагч (client)** болон **захиалагч (customer)**-д зориулсан AI туслах чатбот.
Энэ репод мөн чатботыг ажиллуулах орчин бий: мэдлэгийн сангийн CMS, оператор руу шилжүүлэх хэсэг, сайжруулалтын давталт.
RFP «20260831 RFP training request for Khyazgaargui»-ийн 1–3-р бүлгийг хэрэгжүүлсэн.
TokTok-ийн апп болон вэбэд хавчуулж ашиглах зориулалттай. Монгол хэлний кирилл болон латин бичгийн аль алиныг ойлгоно.

**Одоогийн байдал (2026-10):**

- **1-р шат (`GATEWAY_MODE=faq_only`):** TokTok-ийн API хараахан холбогдоогүй тул бот хувийн мэдээлэлд хандахгүй. Зөвхөн мэдлэгийн сангаас хариулж, шаардлагатай үед оператор руу шилжүүлнэ.
- **Хэрэглэгчид:** Хүргэгч болон харилцагчийн бот идэвхтэй. Захиалагчийн ботын код бий ч одоохондоо `/demo` хуудсанд нуусан.
- **AI загвар:** Туршилтад Google Gemini (үнэгүй хувилбар), production-д Claude ашиглахаар бэлдсэн. Эцсийн сонголтыг TokTok шийднэ.
- Ажлыг үргэлжлүүлэх дэлгэрэнгүй контекст: [`docs/project-context.md`](docs/project-context.md)
- TokTok-ийн техникийн багт өгөх суулгах заавар: [`docs/handoff-toktok.md`](docs/handoff-toktok.md)

```
[Хэрэглэгч]  widget.js (вэб popup) / /embed (апп WebView)   /demo (бүтэн дэлгэцийн туршилт)
     │ SSE стриминг / оператортой ярих үед polling
[Ажилтан]  /admin (Operation баг, админ)   /operator (оператор)   ← SSO (Google / Microsoft)
     │
[FastAPI + LangGraph]
   ① Хамгаалалт (guardrail) → санааны ангилал (intent)
   ② Мэдлэг: хэмжээнээс хамаарч автоматаар сонгоно
        · Бүтэн горим: нийтлэгдсэн FAQ-г бүхэлд нь кэштэй system prompt-д хийнэ (хайлтаас юу ч алдагдахгүй)
        · RAG горим: Qdrant хосолсон хайлт (BM25 + вектор, RRF) + сонголтоор rerank / contextual retrieval
   ③ Агент (Tool Use) → захиалга шалгах, хаяг солих, харилцагчийн хүсэлт, оператор руу шилжүүлэх
      (faq_only горимд зөвхөн оператор руу шилжүүлэх хэрэгсэл үлдэнэ)
   ④ Оператор: ижил чатанд оператор хариулна → шийдсэний дараа бот руу буцна (ярианы агуулга дамжина)
   ⑤ Үнэлгээ: хариултын тодорхой хэсгийг AI шүүгч (judge) үнэлнэ → сайжруулалт FAQ-ийн ноорог үүсгэнэ
     │
[Өгөгдөл]  PostgreSQL 16 + pgvector (яриа, мэдлэгийн хувилбар, ажилтан, аудит, шилжүүлэг)
           Redis 7 (идэвхтэй яриа 24 цаг, түгжээ, хурдны хязгаар, мэдлэгийн багц)
           Qdrant 1.19 (хайлтын индекс, бүх replica хуваалцана)
[Хяналт]  Langfuse (trace, хэрэглэгчийн үнэлгээ, AI шүүгчийн оноо)
```

| Операторын дугаар руу холбох | Чат доторх шилжүүлэг + утасны дугаар |

| Client: ажлын цаг, амралт, хэрэглэгч нэмэх г.м. | Partner багт бүтэцтэй хүсэлт илгээнэ (дансны өөрчлөлтийг чатаар хийхгүй) |
| Driver: шинэ хүргэгчийн onboarding | Профайлын дутуу алхмыг шалгаж зааварчилна |

RFP-ийн 4-р бүлгээс хойших ажил (CRM сегмент, цэсний OCR, маршрут оновчлол, дүрэмт хувцас шалгах) тусдаа шатанд хийгдэнэ.

## Ажилтны хэрэглээ

### Эрх

| Эрх | Юу хийж чадах |
|---|---|
| Оператор (`operator`) | `/operator`: оператор руу шилжсэн яриаг хүлээж авах, хариулах, шийдэх; мэдлэгийн сан, ботын зааврын ноорог бичих, засах, хянуулахаар илгээх, бөөнөөр оруулах, урьдчилж харах; өнгөрсөн яриаг харах (Түүх) |
| Админ (`admin`) | Бүх зүйл (`/admin`): батлах / буцаах, нийтлэх, өмнөх хувилбар руу буцаах, архивлах, үзүүлэлт, яриа ба CSV экспорт, сайжруулалт, ажилтны удирдлага, аудит лог. Өөрийн өөрчлөлтийг ч батлах боломжтой |

Операторын илгээсэн өөрчлөлт админ баталсны дараа л ботод хэрэгжинэ. Батлах товч зөвхөн `/admin`-д байна: админ `/operator` хуудсаар орсон ч тэнд харагдахгүй. Ажилтан компанийн Google / Microsoft бүртгэлээрээ (SSO) нэвтэрнэ.

### Мэдлэгийн сан шинэчлэх (`/admin` эсвэл `/operator` → Мэдлэгийн сан)

1. Баримтыг нээж засаад «Ноорог хадгалах» дарна.
2. «Урьдчилж харах» дээр нийтэлбэл бот хэрхэн хариулахыг шалгана.
3. «Хянуулахаар илгээх» дарна.
4. Админ `/admin` → «Хянах» табаас өөрчлөлтийг харьцуулж үзээд «Батлах» дарвал шууд нийтлэгдэнэ. Буцаахдаа тайлбар заавал бичнэ. Өмнөх шийдвэрүүдийг «Хянасан түүх»-ээс харна (аудит логоос гаргадаг).
5. Алдсан бол «Түүх»-ээс дурын хувилбар руу буцааж болно. Түүх дарагдаж устахгүй.

- **Хайх, шүүх:** Гарчиг, ID, tag болон агуулгаар хайна. Шүүлтүүрүүд: төрөл, төлөв, хэнд харагдах (chatbot / дотоод), хэн нэмсэн, tag. Төлөвийн шүүлтүүрээр «шалгах хугацаа өнгөрсөн», «бот ашиглаагүй», «👎 авсан» баримтуудыг ялгаж болно. Сүүлд засварласан, удаан шалгаагүй, нэр, ашиглалт, 👎-ийн тоогоор эрэмбэлж, хуудаслан харна.
- **Чанарын шалгалт:** Засах үед давхардсан эсвэл зөрчилдсөн FAQ-г автоматаар илрүүлж харуулна (`backend/app/cms/quality.py`). Баримт бүр хэдэн хариултад ашиглагдсан, хэдэн 👎 авсныг мөн харуулна.
- **Excel / Google Sheets-ээс бөөнөөр оруулах:** Баганууд нь `persona, question, answer` (сонголтоор `id, tags, visibility`). Жишээ файл: [`samples/kb-import-sample.xlsx`](samples/kb-import-sample.xlsx). Нэг удаад 5 MB, 2,000 мөр хүртэл оруулна. Оруулсан мөрүүд хянуулах дараалалд орно.
- Явагдаж буй ярианд ч шинэчлэл дараагийн мессежээс эхлэн хэрэгжинэ (`<knowledge_updates>` хэлбэрээр нэмэгдэнэ).
- `backend/knowledge/` доторх «Анхны жишээ» баримтууд анх асахад v1 болж орно.

### Ботын заавар (`/admin` эсвэл `/operator` → Ботын заавар)

System prompt 2 хэсэгтэй.

- **Түгжээтэй дүрэм** (кодонд, зөвхөн хөгжүүлэгч өөрчилнө): үндэслэлгүй хариулт өгөхгүй, хувийн мэдээлэл хамгаална, баталгаажуулах шаардлагатай үйлдэл, яаралтай үед шилжүүлэх г.м.
- **Засагдах заавар** (хэрэглэгчийн төрөл бүрээр, Operation баг засна): өнгө аяс, хариултын хэл, урт, анхаарах сэдэв, шилжүүлэх бодлого, хэрэгслийн хэрэглээ. Түгжээтэй дүрэмтэй зөрчилдвөл түгжээтэй дүрэм давамгайлна.

Засагдах зааврыг мэдлэгийн сантай ижил урсгалаар удирдана: оператор ноорог бичиж илгээнэ, админ батална, түүхээс буцаана. Аудит логт `prompt.*` гэж бүртгэгдэнэ.

Нийтэлсэн заавар **шинээр эхлэх яриа**-нд хэрэгжинэ. Явагдаж буй ярианы system prompt өөрчлөгдөхгүй.

Урьдчилж харахдаа ижил асуултад одоогийн болон засаж буй зааврын хариултыг зэрэгцүүлж харьцуулна. Анхны утга нь `backend/app/personas/prompts.py`-ийн `DEFAULT_INSTRUCTIONS`, анх асахад v1 болж бүртгэгдэнэ («Анхны заавар»).

### Оператор (`/operator` → Чат, Түүх)

Бот шилжүүлэхэд яриа «Хүлээгдэж буй» хэсэгт гарна. Тэнд бот-той хийсэн ярианы түүх болон AI-ийн хураангуйг харна. Шинэ яриа эсвэл хэрэглэгчийн хариу ирэхэд табын гарчигт тоо гарч, дуу болон браузерын мэдэгдэл ирнэ.

1. «Хариуцаж авах» дарж хариуцагч болно.
2. Хариу бичихэд хэрэглэгчийн чатанд шууд очно. Popup хаалттай бол товчин дээр улаан тоо гарна.
3. «Шийдсэн» дарвал бот руу буцна. Шийдвэрийн тэмдэглэл болон харилцсан агуулга ботод дамжина.

Хэрэглэгч оператор хүлээж байхдаа «Шинэ яриа» дарвал хүсэлт автоматаар хаагдаж, дараалалд үлдэхгүй.

«Түүх» табаас өнгөрсөн яриаг шүүж харна. Шүүлтүүрүүд: intent, ангилал, оператор, алдаа, ID-аар хайх.

Одоо байгаа helpdesk системтэй холбох бол `HANDOFF_WEBHOOK_URL`-ийг тохируулна. Тэгвэл бүх үйл явдал HMAC гарын үсэгтэйгээр тийш дамжина.

### Яриа (`/admin` → Яриа)

Бүх яриаг шүүж харна. Шүүлтүүрүүд: хэрэглэгчийн төрөл, огноо, шилжсэн эсэх, 👎, текст.

Яриа бүрийн бүтэн дарааллыг харна: мессеж, ашигласан мэдлэг (дарж нээнэ), хэрэгсэл, хариу өгсөн хугацаа, үнэлгээ, операторын мессеж.

Бүх мессежийг CSV болгон татаж авна (зөвхөн админ, аудит логт бүртгэгдэнэ). Хэрэглэгчийн чат хөтөчийн `localStorage`-д хадгалагдана: хуудсыг refresh хийсэн эсвэл табыг хаасан ч сэргэнэ, оператортой ярьж байсан бол тэр нь ч үргэлжилнэ.

### Сайжруулалт (`/admin` → Сайжруулалт)

Дараах хариултуудыг сэдвээр ангилна:

- оператор руу шилжсэн асуултууд;
- 👎 авсан хариултууд;
- AI шүүгч «үндэслэлгүй» гэж үнэлсэн хариултууд.

Мэдлэгийн санд байхгүй сэдэв дээр FAQ-ийн ноорог автоматаар үүснэ.

- Ноорог **автоматаар нийтлэгдэхгүй**.
- AI мэдэх боломжгүй утга (үнэ, хугацаа г.м.) `[ТОДРУУЛАХ: …]` хэлбэрээр үлдэнэ. Operation баг үүнийг бөглөөд хянуулахаар илгээнэ.

## Ажиллуулах

### Docker Compose

```bash
cp .env.example .env     # LLM-ийн түлхүүр, OIDC_*, STAFF_SESSION_SECRET (32+ тэмдэгт) г.м. тохируулна
docker compose up --build
# http://localhost:3000           popup туршилт
# http://localhost:3000/demo      бүтэн дэлгэцийн чат
# http://localhost:3000/admin     Operation (мэдлэг, үзүүлэлт, сайжруулалт)
# http://localhost:3000/operator  оператор
```

### Локал хөгжүүлэлт (API түлхүүр, SSO-гүйгээр ажиллана)

macOS / Linux:

```bash
cd backend && python -m venv .venv && . .venv/bin/activate && pip install -e ".[dev]"
LLM_PROVIDER=fake uvicorn app.main:app --port 8000   # DB/Redis/Qdrant тохируулаагүй бол санах ойд ажиллана
cd frontend && npm install && npm run dev            # http://localhost:3000
```

Windows (PowerShell). Өгөгдлийн санг Docker-оор асааж, тохиргоог `.env`-д бичнэ:

```powershell
docker compose up -d postgres redis qdrant
cd backend; .\.venv\Scripts\python -m uvicorn app.main:app --port 8000 --loop asyncio:SelectorEventLoop
cd frontend; npm run dev
```

Windows дээр `DATABASE_URL` ашиглах бол `--loop asyncio:SelectorEventLoop` заавал хэрэгтэй: psycopg нь Proactor loop дээр ажилладаггүй.

- Хөгжүүлэлтийн орчинд (`ENV=dev`) `/admin`, `/operator` дээр туршилтын нэвтрэлт (дурын имэйл + эрх) гарна. Production-д идэвхгүй.
- Туршилтын токенууд: `demo-driver`, `demo-driver-new`, `demo-client`, `demo-customer` (`GATEWAY_MODE=mock` үед).
- Python 3.11+ (CI 3.13), Node.js 22, Next.js 16.

### Гол тохиргоо (`.env`)

Бүрэн жагсаалт болон тайлбарыг [`.env.example`](.env.example)-аас харна.

| Тохиргоо | Утга | Тайлбар |
|---|---|---|
| `LLM_PROVIDER` | `anthropic` / `gemini` / `fake` | `anthropic` бол production. `gemini` нь үнэгүй туршилт: `GEMINI_API_KEY`, Gemini загварын нэрийг `AGENT_MODEL` / `CLASSIFIER_MODEL`-д, `LLM_REFUSAL_FALLBACKS=false` тохируулна. Ачаалал ихтэй (503) эсвэл квот дууссан (429) үед `GEMINI_FALLBACK_MODELS`-ийг дарааллаар оролдоно. `fake` бол түлхүүргүй офлайн туршилт |
| `GATEWAY_MODE` | `mock` / `faq_only` | `mock`: туршилтын бүртгэл, хуурамч захиалга (зөвхөн хөгжүүлэлтэд). `faq_only`: 1-р шат, хувийн мэдээлэлгүй, нэргүй хэрэглэгч (`anon:<persona>:<id>`) |
| `KNOWLEDGE_MODE` | `auto` / `full` / `rag` | `auto` үед мэдлэг `FULL_CONTEXT_MAX_TOKENS` (анхдагч 50,000 токен)-д багтвал бүтэн горим, эс бөгөөс RAG |
| `HANDOFF_MODE` | `inchat` / `phone` | `inchat`: оператор ижил чатанд хариулна. `phone`: зөвхөн тикет + утасны дугаар |
| `RATE_LIMIT_PER_MINUTE` | 20 | Хэрэглэгч тус бүрийн минутын хязгаар. Нэг IP-д ногдох хязгаар нь `RATE_LIMIT_PER_IP_PER_MINUTE` (анхдагч 120) |

### SSO тохиргоо

| IdP | Тохиргоо |
|---|---|
| Google Workspace | Google Cloud Console → OAuth client (Web). Redirect URI: `https://<api>/api/auth/callback`. `OIDC_ISSUER=https://accounts.google.com` |
| Microsoft Entra ID | App registration → Web redirect URI нь дээрхтэй ижил. `OIDC_ISSUER=https://login.microsoftonline.com/<tenant-id>/v2.0` |

Анхны админыг `STAFF_BOOTSTRAP_ADMINS=["you@toktok.mn"]`-ээр үүсгэнэ. Бусад ажилтныг `/admin` → Ажилтнууд хэсгээс нэмнэ. `OIDC_ALLOWED_DOMAINS`-д ороогүй домэйноор нэвтрэх боломжгүй.

## TokTok-ийн системтэй холбох

Дэлгэрэнгүй алхмыг [`docs/handoff-toktok.md`](docs/handoff-toktok.md)-ээс үзнэ.

1. **Вэб (popup):** Хуудсанд `widget.js`-ийг нэмнэ. Баруун доод буланд шар товч гарч, дарахад чат нээгдэнэ. Утасны өргөнд бүтэн дэлгэцээр нээгдэнэ.
   ```html
   <script>
     window.TokTokChat = {
       origin: "https://chat.toktok.mn",   // /embed байрлах хаяг
       persona: "driver",                   // driver | client
       // getToken: async () => currentUserToken(),   // 2-р шат: нэвтэрсэн хэрэглэгчийн токен
     };
   </script>
   <script src="https://chat.toktok.mn/widget.js" async></script>
   ```
   1-р шатанд `getToken`-ийг оруулахгүй. Тэгвэл нэргүй ID ашиглана. API: `TokTokChat.open()`, `.close()`, `.toggle()`.
2. **Апп (WebView) / iframe:** `/embed`-ийг нээж, токеныг `postMessage({type: "toktok-auth", token, persona})`-оор дамжуулна. Токеныг URL-д хэзээ ч бичихгүй.
3. **Gateway (2-р шат):** `backend/app/tools/gateway.py`-ийн `TokTokGateway`-г TokTok-ийн API-аар хэрэгжүүлж, `MockTokTokGateway`-г солино. Хэрэглэгчийг таних эхлэл нь `resolve_user(token)`.
4. **Мэдлэг:** `backend/knowledge/` доторх баримтууд нь анх асахад v1 болж орох **жишээ** юм (дүнгүүд нь `[X₮]` гэх мэт орлуулагч). Үүнээс хойш CMS үндсэн эх сурвалж болно.

## Дизайны шийдвэрүүд

- **Загвар:** Claude-ээр ажиллахад хариултыг `claude-opus-5-5` (`effort: low`), ангилал болон AI шүүгчийг `claude-haiku-5-5`, сайжруулалтын шинжилгээг Opus гүйцэтгэнэ. Татгалзсан үед `fallbacks: "default"`-оор автоматаар өөр загвар руу шилжинэ. Туршилтын үед Gemini ашиглана (`LLM_PROVIDER=gemini`).
- **Бүтэн горим (анхдагч `auto`):** FAQ нь `FULL_CONTEXT_MAX_TOKENS`-д багтвал system prompt-д бүтнээр нь хийнэ. Кэшээс уншихад хямд учир хайлтын алдаагүй болгох нь зардлын хувьд үр ашигтай. System prompt-ийг яриа бүрт тогтмол байлгаж, шинэчлэлийг нэмэлтээр дамжуулдаг тул кэш болон thinking зөрөхгүй.
- **Түүхийг зөвхөн нэмнэ:** Thinking блок өмнөх яриатай холбоотой тул өнгөрсөн мессежийг дахин бичихгүй.
- **Qdrant:** Түлхүүр үгийн хайлтыг (бичгийн зөрүүг шингээсэн) sparse вектор болгож, dense вектортой сервер талд RRF-ээр нэгтгэнэ. Индексийг бүх replica хуваалцаж, нийтлэлтийн өөрчлөлтийг revision дугаараар илрүүлнэ.
- **Тусдаа сан:** Чатбот TokTok-ийн өгөгдлийн санд хүрэхгүй, өөрийн PostgreSQL-тэй.
- **Аюулгүй байдал:** Ажилтан SSO-оор нэвтэрнэ (PKCE, state, nonce, JWKS шалгалт). Cookie-тэй бичих хүсэлтэд CSRF header заавал шаардана. Бүх үйлдэл аудит логт бүртгэгдэнэ. `ENV=prod` үед дараах тохиолдолд сервер асахаас татгалзана:
  - нууц утгууд анхдагч хэвээрээ байх;
  - SSO тохируулаагүй байх;
  - `LLM_PROVIDER=fake` байх;
  - `GATEWAY_MODE=mock` байх;
  - DB эсвэл Redis тохируулаагүй байх.

## Шалгагдаагүй зүйлс

- Жинхэнэ загвар дээрх хариултын чанарыг (evals) Claude-ээр бүрэн шалгаагүй.
- Voyage (embedding, rerank), Langfuse, жинхэнэ Google / Microsoft нэвтрэлтийн холболтыг шалгаагүй.
- Claude-ийн дуудлагыг жинхэнэ SDK + хуурамч HTTP-ээр, SSO-г RS256 гарын үсэгтэй хуурамч IdP-ээр, өгөгдлийн санг жинхэнэ PostgreSQL 16 + pgvector / Redis / Qdrant 1.19 дээр шалгасан.
- Дэлгэцийг браузераар шалгасан: «хэрэглэгч → оператор → шийдсэн → бот руу буцах» урсгал болон «засах → хянах → батлах» урсгал.
- TokTok-ийн жинхэнэ API-тай холболт техникийн тодорхойлолт ирэхийг хүлээж байна.
